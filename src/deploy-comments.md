- Session 31: Fix — Buy Now was silently wiping unrelated cart items on fulfillment. webhook.ts's handleCheckoutSessionCompleted() called clearCartForUser(userId) unconditionally after every purchase, deleting the buyer's entire persisted cart rather than just what was bought — invisible for a full-cart checkout (everything in the cart was purchased anyway) but a real data-loss bug for the single-item Buy Now path added in Session 30 (a buyer with an unrelated item already in their cart lost it on an unrelated Buy Now purchase, no error surfaced). Fixed by scoping cart-clearing to the productIds actually charged for: new removeCartItemsForUser(userId, productIds) helper in cart.ts replaces the old unconditional clear, fed from the same full.line_items already used for fulfillment (no second fetch). clearCartForUser removed entirely — confirmed via repo-wide grep as its only caller. Live-tested this session (see the Checkout Sessions/Wire Buy Now updates above) — confirmed fixed for real, not just via code diff.

- Session 31: Real refunds via Stripe Refunds API — refunds.ts's dbResolveRefundClaim no longer scopes by the admin's own userId (real bug: approving a refund silently no-op'd for any claim that wasn't the admin's own account); now gated by id + status='pending' as an idempotency guard, calls stripe().refunds.create() before flipping the claim's status (a failed Stripe call leaves the claim retryable, never falsely approved). New markSingleDownloadRefunded (downloads.ts, per-download-scoped, replacing the now-dead session-scoped markDownloadsRefunded) and clawbackLoyaltyPointsForBuyer (loyalty.ts, unconditional, can go negative — a clawback isn't a voluntary redemption) wired into the approval path alongside the existing voidAffiliateLedgerForDownload. Also fixed a second real bug caught during this work: the old approval flow credited loyalty points back to the admin's own account instead of the buyer's, via a caller-session-scoped helper being reused server-side. RefundClaimsManager.tsx's approve action now only calls approveRefundClaim; the "restore points" toggle was removed since it no longer controlled anything real. Not yet live-tested — pushed but the five live-sandbox verification tests (partial refund, retry/idempotency, cross-buyer approval, negative-balance clawback, reject-path no-op) haven't been run yet.
